# Holic100 PWA — v0.1 (プレイ可能な初期版)

iPad（Safari / ホーム画面に追加）、PC、Androidのブラウザで動く、1人対CPU3人のカードゲームです。外部ライブラリとバックエンドを使用していません。

## ルール（確定事項）

- **現在の手札に100未満を保てる札が1枚もないプレイヤーは、カードを出す前に自動脱落**。安全な選択肢があるのに100以上となるカードを自ら出した場合も脱落。\n- 人間プレイヤーが脱落したときは通知ダイアログを表示し、確認後もCPU同士の対戦を観戦可能。
- **Holic100は例外なし**。出すと合計100、出した本人が必ず脱落（B方式）。
- 4人（人間1人、CPU3人）。最後に残った1人が勝者。
- 全58枚：1〜10各4、−10×4、Reverse×4、Holic100×4、Change 2×2、Change 4×2、Double×2。
- 手札は必ず固定スロット0〜3。**自動ソート禁止**。場に出したカードの位置に補充。
- 山札が尽きたら、捨て札の一番上以外をシャッフルして山札を作る。
- Double：次の人が2枚連続で出す。1枚目は数字札1〜10または−10のみ。両方ともない場合のみ即脱落。1枚目に出したカードのスロットには補充される。2枚目は任意のカード。
- Change 2：出したスロットへ補充→相手指名→自分の2スロットを指定→対象の**元の4枚**からランダム2スロットを引いて交換。対象の選ばれなかった2スロットは不変。
- Change 4：出したスロットに補充→相手指名→両者の4スロットをそのまま全交換。

## 今回の実装上の補完ルール（後で変更可能）

- 脱落者の未使用カードは山札に戻さず、ゲーム外に除外します（総58枚の整合は維持）。
- Doubleの2枚目にDoubleを出した場合は、次のプレイヤーが新たに2枚連続プレイします。
- Reverseの効果はカードを出した瞬間に適用され、次プレイヤー選出にも反映されます。
- CPUはHolic100を攻撃カードとみなしません（使用すると必ず自身が脱落するため）。他の選択肢がない場合だけ出します。
- CPUのChange 2は相手の各スロットのカード滞留ターン数からターゲットを評価し、自分のHolic100（自爆札）、小数字札などから2枚を優先して手渡します。
- CPUの4スロットのカード背面は固定配置。プレイ位置と補充位置がアニメーションで確認できます。
- 現段階のCPUは公開スロット位置・滞留時間と手札を使うヒューリスティックです。相手のカードの実内容を覗きません。

## iPadだけでGitHub Pagesに公開するまで

1. `holic100_pwa.zip` をiPadの「ファイル」アプリに保存します。
2. SafariでGitHubを開き、`holic100` というリポジトリを作ります。ソースコードを公開したくなければ最初はprivateで構いません。
3. リポジトリにこのZIPをアップロードします。Codex CloudのGitHub連携を設定できたら、`CODEX_HANDOFF.md` の指示でZIPを展開し、内容をリポジトリ直下にコミットさせてください（ZIPは展開後削除）。
4. `npm test` を実行し、テストが通ることを確認します。
5. GitHub Pagesを有効化（`Settings` → `Pages` → `Deploy from a branch` → `main` / `/(root)`）。無料プランでPages公開する場合は通常、リポジトリをpublicにする必要があります。
6. 数分後にPagesのURLをSafariで開きます。共有メニューから「ホーム画面に追加」を実行するとPWAになります。

**注意**: ZIPの中の`index.html`をiPadから直接開くだけでは、JavaScriptモジュールやService Workerが動作しない場合があります。PagesなどHTTPSでのホスティングが必要です。ホーム画面アイコンの使用・横向き表示の挙動はiPadOSのバージョンによって異なります。

## Windows / Codex Cloudのローカルテスト

Node.js 18以降があればテストは依存関係のインストールなしで実行できます。

```bash
npm test
python3 -m http.server 8000
```

ローカル確認はブラウザで `http://localhost:8000/` を開きます。

## ファイル構成

- `index.html`: 対戦テーブルと操作UI
- `style.css`: iPad横向きを優先したレスポンシブデザイン
- `game.js`: 58枚のカード・ゲーム状態・CPUロジック
- `app.js`: タップ操作・CPUの動作・アニメーション・自動保存
- `manifest.webmanifest`: PWA定義
- `sw.js`: オフライン用キャッシュ
- `icons/`: 192px / 512pxアイコン
- `tests/game.test.js`: 25件のルールテスト（100対戦のシミュレーションを含む）

## 既知の制限

- 現時点ではiPad実機での表示・タッチ操作確認は未実施です。
- カードの視覚的な移動演出は最低限（CPUのスロット位置を変えずに出札と補充を強調）。追加のアニメーション改善余地があります。
- AIの心理戦は指定ヒューリスティックに基づく最初の実装です。強さ調節UIや高度な確率推定AIは未実装です。
- セーブデータは同一ブラウザ内のローカルストレージに保存されます。ブラウザデータを削除すると失われます。
- 更新時には `sw.js` の `CACHE` 識別子を変えてください。変更しないと端末の古いキャッシュが使われることがあります。
