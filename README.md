# Holic100 PWA

iPad横画面向け、人間1人＋CPU3人のカードゲームです。ゲームの配信にはCloudflare Pages＋Pages Functionsの共通パスワード認証が必要です。オフラインプレイは無効です。

## 開発・認証

[認証の構成・Cloudflare設定・検証記録](docs/cloudflare-auth.md)を参照してください。パスワードと署名鍵はフロントエンドやこのリポジトリへ保存せず、Cloudflareの暗号化されたSecretとしてProductionとPreviewの両方に登録します。

Node.js 24以降、npm、Python不要、ローカルTLS生成用のOpenSSLを使用します。

```bash
npm ci
npm run setup:local
npx wrangler d1 migrations apply AUTH_DB --local
npm test
npm run build
npm run serve
```

ローカル専用の `.dev.vars`、`wrangler.jsonc`、`.wrangler/` はGit対象外です。`setup:local` は既存ファイルを上書きせず、本番設定を作成しません。ローカルログインでは `.dev.vars` の使い捨てテスト用値を使用します。チャットやログへ転記しないでください。HTTPSのテスト用証明書はローカルでのみ信頼してください。

`dist/` のみをPagesのビルド出力に使用し、必ずPages Functionsを含めて配信します。Pythonの静的HTTPサーバー、GitHub Pages、静的ファイルだけのDirect Uploadでは認証が動きません。現時点で本番・プレビューへのデプロイはしていません。

## ルール（確定事項）

- **現在の手札に100未満を保てる札が1枚もないプレイヤーは、カードを出す前に自動脱落**。安全な選択肢があるのに100以上となるカードを自ら出した場合も脱落。
- 人間プレイヤーが脱落したときは通知ダイアログを表示し、確認後もCPU同士の対戦を観戦可能。
- **Holic100は例外なし**。出すと合計100、出した本人が必ず脱落（B方式）。
- 4人（人間1人、CPU3人）。最後に残った1人が勝者。
- 全58枚：1〜10各4、−10×4、Reverse×4、Holic100×4、Change 2×2、Change 4×2、Double×2。
- Change 2の交換後も、選ばれなかったスロットは一切移動しない。
- 手札は必ず固定スロット0〜3。**自動ソート禁止**。場に出したカードの位置に補充。
- 山札が尽きたら、捨て札の一番上以外をシャッフルして山札を作る。
- Double：次の人が2枚連続で出す。1枚目は数字札1〜10または−10のみ。両方ともない場合のみ即脱落。1枚目に出したカードのスロットには補充される。2枚目は任意のカード。
- Change 2：出したスロットへ補充→相手指名→自分の2スロットを指定→人間は対象CPUの**裏向き4スロットから2つをタップ**して確定→交換（ババ抜き方式）。CPUも相手の札の中身は参照せず、2スロットをランダムに選択。確認までは双方の手札を変えない。対象の選ばれなかった2スロットは不変。
- Change 4：出したスロットに補充→相手指名→両者の4スロットをそのまま全交換。

## 今回の実装上の補完ルール（後で変更可能）

- 脱落者の未使用カードは山札に戻さず、ゲーム外に除外します（総58枚の整合は維持）。
- Doubleの2枚目にDoubleを出した場合は、次のプレイヤーが新たに2枚連続プレイします。
- Reverseの効果はカードを出した瞬間に適用され、次プレイヤー選出にも反映されます。
- CPUはHolic100を攻撃カードとみなしません（使用すると必ず自身が脱落するため）。他の選択肢がない場合だけ出します。
- CPUのChange 2は相手の各スロットのカード滞留ターン数からターゲットを評価し、自分のHolic100（自爆札）、小数字札などから2枚を優先して手渡します。
- CPUの4スロットのカード背面は固定配置。プレイ位置と補充位置がアニメーションで確認できます。
- 現段階のCPUは公開スロット位置・滞留時間と手札を使うヒューリスティックです。相手のカードの実内容を覗きません。

## ファイル構成

- `game.js`：既存のゲームルールとCPU。今回変更なし。
- `app.js`／`index.html`／`style.css`：ゲームUI。ログアウトフォームと認証状態確認を追加。
- `functions/_middleware.js`／`server/auth.js`：配信認証、ログイン、セッション、レート制限。
- `auth-client.js`：セッション・通信喪失時に開いている画面をログインへ戻す処理。
- `sw.js`：旧キャッシュ削除とネットワーク専用配信。ゲームのオフラインキャッシュは使用しません。
- `migrations/`：D1レート制限・失効可能なセッション記録。
- `tools/build.mjs`：ゲーム配信ファイルだけを `dist/` に配置。全パスをFunctionsへ通す `_routes.json` を生成。

## 検証と制限

今回の検証は [認証の検証記録](docs/cloudflare-auth.md) を参照してください。iPad実機Safariは未検証です。ホーム画面への追加と横画面用Manifestは維持しています。ログアウト時はブラウザのキャッシュ・保存データも削除します。

過去の [PR #2検証記録](docs/pr2-validation.md) は当時の仕様です。オフライン成功を前提とする旧ブラウザスクリプトは認証版には使用せず、認証版の検証スクリプトを使用してください。
